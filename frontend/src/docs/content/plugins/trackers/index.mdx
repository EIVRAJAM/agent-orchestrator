---
title: Issue tracking
description: Opt-in GitHub and GitLab issue intake with a default-off PR-ready comment.
---

Orchestrator has GitHub and GitLab issue adapters. The existing [GitHub intake guide](/plugins/trackers/github) explains the shared opt-in flow; choose `gitlab` for GitLab projects. Linear and external Node tracker plugins are unsupported.

Tracker intake needs both a per-project opt-in and the daemon-wide `AO_TRACKER_INTAKE` flag, which defaults off. Once both are on it can discover matching GitHub or GitLab issues and spawn workers. Intake is read-only by default.

Projects can separately opt into one conservative write-back: when a session's PR is ready for review and its CI is green, Orchestrator posts one short, deterministic comment containing the PR link. It never closes or transitions issues, changes labels/assignees, or merges. The delivery outbox is at-most-once: an ambiguous provider response is recorded as uncertain and is not retried blindly, because the comment may already have been posted.

<Callout type="warn">
	The tracker lane is still limited. Do not treat issue association as a complete two-way synchronization workflow.
</Callout>

Use the SCM capability for pull requests, CI, reviews, and mergeability; those facts are independent from tracker intake. The write-back is disabled unless the project enables `trackerWriteback`.
